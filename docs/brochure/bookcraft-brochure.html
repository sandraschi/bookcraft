Full-power Calibre library manager in pure Rust: search, inspect, edit, add, remove,

convert, and ingest for the Storytold ArtCraft suite.

One binary, three surfaces: bookcraft-cli <verb> for humans and scripts,

bookcraft-cli mcp for agents over stdio, and the bookcraft-app desktop shelf.

All three call bookcraft_core::dispatch, so they cannot disagree.

**Status: v0.5.0 - L1 core, L2 CLI/MCP (30 tools) and the L3 shelf (11 views: now with

covers, in-shelf reading and multi-select bulk work), all verified (46 tests).

Democraft recipes live in democraft-mcp. See HANDOVER.md.**

Guarantees

  • Writes go through Calibre's own rules. Reads open metadata.db read-only. Every

mutation is direct SQL inside one IMMEDIATE transaction with a 30-second busy timeout,

registering the same title_sort/uuid4 functions Calibre's triggers call.

calibredb is deliberately not used: it refuses every local operation while any Calibre

program runs. A database that is not a Calibre library is rejected on open.

  • A backup is taken first. Every mutation copies metadata.db (plus the full-text

index) to a timestamped backup under %LOCALAPPDATA%\BookCraft\backups (reused while

younger than 120 s); the backup path is in every mutation result. book backup takes

one on demand.

  • Conversion output never overwrites. bookcraft convert writes into the --out_dir you

name and picks <title>-2.<ext> when the name is taken.

  • Removed books are recoverable. remove-book moves the book directory to the trash

area beside the backups; only --permanent deletes. The database row is always removed

through Calibre's own cascade trigger.

  • Confinement is enforced when you ask for it. Pass --root DIR (or BOOKCRAFT_ROOT) and

every library, input and output path must resolve beneath it, including .. traversal.

  • No secrets, no network. Readly ingest takes a *saved* HTML page; the live browser path

stays in readly-mcp.

Quickstart

# Build
cargo build --release -p bookcraft-mcp

# Is the converter engine present? What is in the library?
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" status
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" stats

# Find a book, then read its full record
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" search --query "dune"
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" info --id 42 --json

# Search book text when Calibre built its full-text index (reports which engine answered)
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" grep --pattern "blacksmith"

# Convert one book (needs Calibre's ebook-convert on PATH or BOOKCRAFT_EBOOK_CONVERT)
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" convert --id 42 --from EPUB --to txt --out-dir .\outbox

# Edit metadata (backup is automatic; fields: title authors tags series series_index
# publisher rating isbn languages comments pubdate identifiers)
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" update --id 42 --set title="Dune" --set tags="sci-fi, classic" --set rating=4

# Add and remove books (add --empty for a record without files)
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" add-book --file .\dune.txt --title "Dune" --authors "Frank Herbert"
.\target\release\bookcraft-cli.exe --library "D:\Books\Calibre Library" remove-book --id 42

# Turn a saved article page into Markdown
.\target\release\bookcraft-cli.exe ingest --html .\tests\fixtures\sample-issue.html --out .\outbox\issue.md

# MCP server (stdio)
.\target\release\bookcraft-cli.exe mcp

# Desktop shelf (same core, in-process; --smoke runs the headless checks)
.\target\debug\bookcraft-app.exe --smoke
.\target\debug\bookcraft-app.exe

Product Requirements & Architecture Specification

Source plan: mcp-central-docs/projects/craft-fleet-rebuild/PLAN.md §5 #8,

corrected 2026-11-05: BookCraft is a full-power Calibre manager, not a thin subset.

Bucket: A (SQLite + CLI + files) -> Pure-Rust ArtCraft

Status: v0.3.0 L1/L2/L3 shipped with the write path; catalog analytics next.

1. Model

A book is one Calibre row: id, uuid, title, sort, author_sort, authors[], series,

series_index, tags[], formats[], rating, pubdate, last_modified, path, cover,

description, plus the real files on disk.

The same model covers EPUB/PDF prose, PDF magazines, and CBZ/CBR comics because Calibre

stores all of them the same way. BookCraft does not distinguish "book" from "issue" in its

verbs; the format and path tell you what it is.

2. Seam

Concern Owner
Library storage, metadata CRUD, covers, full text BookCraft (direct SQL under Calibre's rules)
Format conversion BookCraft -> Calibre ebook-convert
Saved-page HTML -> Markdown BookCraft ingest
Live magazine scraping, login, browser readly-mcp (unchanged)
Server-side library service, accounts not a craft (calibre-mcp server mode)
Calibre desktop GUI Calibre itself (BookCraft never drives it)

Correction 2026-11-05: the original plan said "library managers are not crafts". That was

the fuckup this revision fixes - BookCraft manages the library. calibredb is not used

because it refuses every local operation while any Calibre program runs; BookCraft writes

SQL itself inside Calibre's own trigger and transaction invariants instead.

4. Recipe targets (implemented in democraft-mcp, not here)

1. book/search-and-info - search a fixture library, dump one record, assert keys.

2. book/convert-roundtrip - EPUB -> PDF/TXT, measure bytes; CBZ -> PDF when a comic fixture

is present.

3. book/fulltext-find - FTS query with snippet; assert the reported engine.

4. book/readly-ingest-sim - tests/fixtures/sample-issue.html -> issue.md, assert title

and word count; never a browser.

5. book/manage-roundtrip - scratch library, backup, add, update, verify, remove;

asserts the round-trip payloads (DONE 2026-11-05).

Fixtures must be repository-local and DRM-free. No real library path goes into a recipe.

5. Safety and failure modes

  • Reads open the library read-only; writes run inside one IMMEDIATE transaction with a

30-second busy timeout, so a held Calibre library fails fast instead of half-writing.

  • Every mutation takes a timestamped backup outside the library first and reports it.
  • remove-book moves files to a trash area by default; only --permanent deletes.
  • add-book rejects duplicates without writing anything unless duplicates/automerge.
  • A non-Calibre metadata.db is rejected on open.
  • --root confinement covers library, inputs and outputs.
  • Conversion never overwrites; the destination is <title>[-n].<ext>.
  • Missing ebook-convert -> status: down + actionable error from convert.
  • Missing full-text-search.db -> engine: metadata_db, not an empty success.
  • Missing format file on disk -> NotFound, not a zero-byte output.
  • Readly tokens never enter this repo; live scraping is out of scope.

6. Non-goals

  • A server with accounts, OPDS, or a web UI.
  • Embedding a converter; Calibre remains the engine.
  • Duplicating readly-mcp's browser automation.

7. Open decisions

1. L3 app: built 2026-11-05, beautified the same day. bookcraft-app ships eleven

views over the same in-process dispatch: covers render from the library's own

files, the Read view pages chapters in-shelf, the Library list multi-selects into

bulk actions. Warm paper-and-amber theme throughout.

2. Comic/manga specifics: CBZ/CBR are convertible through ebook-convert; a dedicated

page-count/cover path is not implemented.

3. Naming: settled - BookCraft is the craft; rust-calibre-mcp stays as the richer

read-only dashboard (see HANDOVER). A hard cutover waits on full parity.

4. Phase B: DONE 2026-11-05 (v0.4.0) - renames, analytics, export, excerpts,

open/random, collections, bulk update, init. See docs/PARITY.md.

5. Phase C (open): semantic search/RAG, online metadata fetch, OPDS/server mode.

Complete MCP Tool & CLI Verb Reference

Thirty tools, all routed through bookcraft_core::dispatch. Both book_status and

book.status are accepted (strict MCP hosts reject dots, ArtCraft ids use them).

Common optional arguments on every tool: library (Calibre directory or metadata.db),

root (confinement root). They default to BOOKCRAFT_LIBRARY / BOOKCRAFT_ROOT, and can be

set once in the client config.

Return shape

Success: a JSON object with "success": true and the fields above.

Failure: {"success": false, "error": "...", "error_type": "not_found|invalid|outside|database|io"}.

MCP wraps the payload as one text content item and sets isError: true when success is

false. Nothing is returned as a binary blob.

Notes

  • Mutations never go through calibredb: it refuses every local operation while any

Calibre program runs. BookCraft writes SQL itself inside Calibre's trigger invariants

(one IMMEDIATE transaction, 30-second busy timeout, title_sort/uuid4 registered).

  • Every mutation takes a timestamped backup outside the library first and reports it;

book_add rejects duplicates unless duplicates or automerge is set.

  • book_remove moves files to a trash area by default; only permanent: true deletes.
  • book_rename merges when the new name exists (deduplicated re-link, then the old row

goes); the affected books keep correct sorts.

  • book_excerpt reads EPUB (paginated chapters) and TXT; PDF and comics are refused

honestly. book_open opens where the server runs, not where the agent sits.

  • book_convert needs Calibre. Without ebook-convert the call fails with not_found; it

never fabricates an output file.

  • book_grep reports which engine answered. A library without full-text-search.db answers

from titles and descriptions only - that is a scope downgrade, and the tool says so.

  • Library, input and output paths must be beneath root when a root is configured.
